# Приемка по заданию — день 2

Проект Erston для Mobile SMARTS реализует приемку товара из заранее назначенного документа.

## Работа вдвоем через GitHub

Код документа разделен на две независимые части:

- `src/documents/part-1/ReceivingWorkflow.erst` — алгоритм приемки;
- `src/documents/part-2/ReceivingInterface.erst` — интерфейс и управление.

Готовые архивы для двух веток находятся в каталоге `team-split`.
Полный порядок работы и список файлов описаны в `TEAM_SPLIT.md`.

## Реализованный процесс

1. Оператор открывает только назначенный документ: создание приемки на терминале отключено.
2. При входе отображается главное меню документа:
   - `Сканировать товар`;
   - `Просмотр набранного`;
   - `Настройки`;
   - `Временный выход`.
3. При выборе сканирования вводится или сканируется номер пломбы, затем номер коробки.
4. Оператор сканирует товары, для каждой товарной позиции обязательно вводится номер партии.
5. Каждая принятая позиция занимает одно грузоместо независимо от введенного количества.
6. При заполнении коробки система закрывает ее и требует следующую.
7. После полного размещения задания документ завершается автоматически.

## Настройки документа

- `Глубина коробок` — по умолчанию 10; доступна только до первого принятого товара.
- `Режим работы` — показывает или скрывает состав задания на экране сканирования.
- `Количество` — автоматическое значение 1 или ручной ввод.

## Контроль требований

- неизвестный товар и товар вне задания не принимаются;
- номер пломбы проверяется через контейнер Mobile SMARTS и имеет формат `001` + четыре цифры;
- номер коробки проверяется через контейнер Mobile SMARTS и имеет формат `00` + цифра, отличная от `1`, + четыре цифры;
- коробка в поле пломбы отклоняется сообщением `Это не пломба.`, а пломба в поле коробки — сообщением `Это не коробка.`;
- превышение количества задания блокируется при записи;
- временный выход сохраняет черновик и возвращает к списку документов только после пароля руководителя `2408`; неверный пароль оставляет оператора в меню;
- ручное закрытие коробки доступно ровно при `ГлубинаКоробок - 2` грузоместах;
- экран «Просмотр набранного» показывает наименование, штрихкод и факт/план, а нажатие на товар открывает партии, коробки и количества;
- детализация товара группирует строки по коробке и партии и суммирует их количество;
- `Esc` на запросе новой коробки после закрытия текущей возвращает в главное меню документа;
- цветное сообщение относится только к экрану, на котором произошло действие, и очищается при переходе в другой раздел;
- для разделения грузомест фактические строки не объединяются и получают уникальный `CargoPlaceId`.

## Сборка и запуск

- `Ctrl+Shift+B` — сборка проекта в VS Code Windows.
- Задача `Erston: Build and deploy` — сборка и публикация в базу `Empty app`.
- Задача `Mobile SMARTS: Start emulator` — запуск Windows-эмулятора.

## Тестовый документ

В базе `Empty app` создан назначенный пользователю `Terminal` документ
`DAY2-RECEIVING-CHECK-001` — «Проверка проекта - 3 товара, 9 грузомест».

Дополнительно созданы документы для проверки интерфейса:

- `DAY2-RECEIVING-CHECK-002` — короткое задание на 4 грузоместа;
- `DAY2-RECEIVING-CHECK-003` — проверка нескольких партий и коробок на 5 грузомест.
- `DAY2-RECEIVING-CHECK-004` — быстрый цикл из 3 грузомест;
- `DAY2-RECEIVING-CHECK-005` — проверка двух коробок на 12 грузомест.
- `DAY2-RECEIVING-CHECK-006` — «Тестовый документ №6», проверка группировки партий и коробок на 9 грузомест;
- `DAY2-RECEIVING-CHECK-007` — «Тестовый документ №7», полный цикл приемки на 14 грузомест.
- `DAY2-RECEIVING-CHECK-008` — «Тестовый документ №8», чистая проверка контейнеров на 2 грузоместа.

Контрольные номера контейнеров:

- пломбы: `0011234`, `0014444`;
- коробки: `0021234`, `0034455`;
- неверный тип для поля пломбы: `0021234`;
- неверный тип для поля коробки: `0011234`;
- неверный формат: `011234`, `00112A4`, `00412345`.

Штрихкоды и требуемое количество:

- `4600000000022` — «Тестовый товар 1 - Вода», 4 шт.;
- `4600000000039` — «Тестовый товар 2 - Сок», 3 шт.;
- `4600000000046` — «Тестовый товар 3 - Печенье», 2 шт.

Для проверки ручного закрытия коробки при глубине 10:

1. Отсканировать первый товар 4 раза.
2. Отсканировать второй товар 3 раза.
3. Отсканировать третий товар 1 раз — в коробке станет 8 грузомест.
4. Выбрать «Закрыть коробку», отсканировать новую коробку.
5. Отсканировать третий товар ещё 1 раз для автоматического завершения документа.
