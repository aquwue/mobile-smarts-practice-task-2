# Разделение проекта для работы в двух ветках

Проект разделен на два независимых функциональных блока. Основной файл
`src/documents/Receiving.erst` теперь содержит только поля документа и точку
входа. Реализация подключается к типу `Receiving` через отдельные блоки
`expand Receiving`.

## Общая часть

Эти файлы должны находиться в базовой ветке до создания рабочих веток:

- `src/documents/Receiving.erst` — объявление документа и функция `Edit`;
- `.vscode/` — сборка, развертывание и отладка;
- `.project/`, `.erston/` — конфигурация проекта и подключения;
- `src/expanded/app.erst`;
- `README.md`.

Общий файл документа содержит 57 строк. После создания веток его желательно
не менять без согласования, чтобы не создавать конфликтов при объединении.

## Часть 1 — алгоритм приемки

Рекомендуемая ветка: `feature/receiving-workflow`.

Основные файлы:

- `src/documents/ReceivingWorkflow.erst` — 544 строки;
- `src/expanded/Containers.erst` — типы контейнеров пломбы и коробки;
- `test-data/day2-product.json`;
- `test-data/day2-receiving.json`;
- `test-data/day2-check-products.json`;
- `test-data/day2-check-receiving.json`.

Функциональность:

- запрос и проверка пломбы;
- запрос и проверка коробки;
- работа через `SelectContainer`;
- сканирование товара;
- поиск номенклатуры по штрихкоду;
- ввод партии и количества;
- запись фактических строк документа;
- контроль превышения задания;
- автоматическое и ручное закрытие коробки во время сканирования.

## Часть 2 — интерфейс и управление

Рекомендуемая ветка: `feature/receiving-interface`.

Основные файлы:

- `src/documents/ReceivingInterface.erst` — 579 строк;
- `src/expanded/DocumentItem.erst`;
- `test-data/day2-interface-check-002.json` … `day2-interface-check-008.json`;
- `test-data/install-test-documents.ps1`.

Функциональность:

- главное меню документа;
- цветные сообщения;
- начальные настройки;
- меню настроек и глубина коробки;
- просмотр набранного товара;
- таблица партий и коробок;
- группировка количества;
- пароль временного выхода;
- общие функции состояния и завершения документа.

## Порядок работы с GitHub

1. Распаковать `common-base.zip` в пустой репозиторий, сделать первый коммит и
   отправить общую часть в ветку `main`.
2. Создать две ветки от одного состояния `main`:

   ```bash
   git switch -c feature/receiving-workflow
   git switch main
   git switch -c feature/receiving-interface
   ```

3. Первый разработчик добавляет файлы из архива `part-1-workflow.zip` в ветку
   `feature/receiving-workflow`. Архив распаковывается прямо в корень проекта;
   дополнительная папка `part-1` не создается.
4. Второй разработчик добавляет файлы из архива `part-2-interface.zip` в ветку
   `feature/receiving-interface`. Архив распаковывается прямо в корень проекта;
   дополнительная папка `part-2` не создается.
5. Каждый делает отдельный коммит и отправляет ветку:

   ```bash
   git add .
   git commit -m "Добавлена часть алгоритма приемки"
   git push -u origin feature/receiving-workflow
   ```

   Для второй ветки используются имя `feature/receiving-interface` и сообщение
   `Добавлен интерфейс приемки`.

6. Объединить обе ветки с `main`. Файлы частей не пересекаются, поэтому обычное
   объединение не должно вызвать конфликтов.
7. После объединения выполнить задачу VS Code `Erston: Build`.

Рабочая сборка требует обе части. Отдельная ветка с одной частью предназначена
для независимого коммита и проверки изменений в GitHub; полностью проект
собирается после объединения веток.
